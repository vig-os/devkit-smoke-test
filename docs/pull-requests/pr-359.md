## [Comment #1](https://github.com/vig-os/devkit-smoke-test/pull/359#issuecomment-5266731532) by [@c-vigo](https://github.com/c-vigo)

_Posted on August 12, 2026 at 12:21 PM_

Closing: this deploy is not salvageable, and the defect it exposed is fixed upstream.

The 1.8.0-rc3 deploy commit removed this repo's own Python project (`pyproject.toml`, `uv.lock`, `src/`, `tests/`) alongside the genuinely-retired `renovate-changelog-*.yml` workflows. The smoke-mode scaffold copy carried `rsync --delete`, which removes every tracked path the devkit template does not ship — harmless while the deploy commit was built additively, destructive once vig-os/devkit#1443 began publishing `git ls-files --deleted`.

That is why `Scaffold Drift` failed: with no `pyproject.toml` on the branch, the gate's re-scaffold no longer detected a Python repo, so it rendered `language: ['actions']` for CodeQL and stripped the Python block from `.gitignore`.

Fixed in vig-os/devkit#1466 (PR vig-os/devkit#1468, merged to `release/1.8.0`): smoke mode now copies without `--delete`, so retirement stays the vig-os/devkit#1348 manifest's job and matches what the drift gate's normal-mode re-scaffold expects. No listener redeploy is needed — `repository-dispatch.yml` is unchanged; its deletion-publishing step now sees only genuine retirements.

The next candidate dispatch opens a fresh deploy PR.
