# [PR 441](https://github.com/vig-os/devkit-smoke-test/pull/441) ci: bind commit-App token jobs to the commit-app environment

## Summary

First live adoption of [devkit#1710](https://github.com/vig-os/devkit/issues/1710). Sets `DEVKIT_COMMIT_APP_ENVIRONMENT=commit-app` in `.vig-os` and re-runs the devkit 1.17.0 scaffold, which binds the commit-App token-minting jobs to the `commit-app` deployment environment (deployment branch policy: `main`, `dev`, `release/*`). The `commit-app` environment already exists on this repo.

Rendered by the scaffold ("Rendered commit-App environment binding: commit-app (8 token-minting job(s))"):

- `prepare-release.yml`: `prepare`, `rollback`
- `prepare-hotfix.yml`: `prepare`, `rollback`
- `release.yml`: `rollback`
- `release-core.yml`: `finalize` (plus its two `COMMIT_APP_*` `workflow_call` secrets flipped `required: true` -> `false`, since a reusable callee's job-level environment secret cannot be delivered through the caller's `secrets: inherit`)
- `sync-issues.yml`: `sync`
- `sync-main-to-dev.yml`: `sync`

No `promote-release.yml` job is touched — this repo is not in mirror mode ([#1424](https://github.com/vig-os/devkit/issues/1424)), so the `reset-sync-mirror` job the knob also covers does not exist here.

Org/repo-level `COMMIT_APP_CLIENT_ID`/`COMMIT_APP_PRIVATE_KEY` stay as the fallback secrets for now; moving them to environment secrets on `commit-app` is left for a later train per the adoption doc.

## Follow-up (not in this PR)

Manual `sync-issues` dispatch on `dev` to verify the environment, then the next train's candidate release exercises `finalize` (the devkit docs flag `finalize`'s job-level environment secret precedence over the caller's inherited one as unverified until a real train runs it).
